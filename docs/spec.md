# Спецификация: редактор вязальных схем

Верхнеуровневая спецификация для запуска цикла wayfinder. Термины — по [CONTEXT.md](../CONTEXT.md); архитектурные решения — в [docs/adr/](adr/).

## Цель

Фронтенд-приложение для составления цветных схем для вязания (спицы, крючок): клетчатая **схема**, где каждая **клетка** — петля, окрашенная **нитью** из **палитры**. Схема печатается в PDF с **линейками** и читается на ч/б принтере благодаря **узорам заливки**.

## Рамки

- Только фронтенд, без бэкенда. Одна открытая схема за раз.
- Десктопный браузер, мышь/трекпад. Только актуальные Chrome, Edge, Firefox, Safari (последние две версии), без полифиллов.
- Интерфейс на русском; все строки — через словарь (vue-i18n).
- Деплой: GitHub Pages из `main` через GitHub Actions.

### Не входит (этап «Потом»)

Выделение / копирование / вставка / отражение; символы петель (лицевая, изнаночная и т.п.); импорт картинок и чужих форматов; раппорт; кисть больше 1×1; тач и стилус; PWA/офлайн; переназначение клавиш; библиотека из нескольких схем; сохранение истории правок между перезагрузками.

Модель клетки и обработка ввода не должны закрывать дорогу этим расширениям: содержимое клетки расширяемо, ввод — через Pointer Events, команды — через единый реестр.

## Модель

### Схема
- Конечная сетка W×H, целевой максимум ~500×500 с плавной работой.
- Каждая клетка: ссылка на нить палитры или **пустая клетка**.
- **Свойства схемы**: название, заметки (свободный текст), **плотность вязания** (петель и рядов на 10 см), **пропорция клетки** (переключатель: «авто» — из плотности, или вручную, по умолчанию 1:1), **направление нумерации** (одна из 4 комбинаций: ряды снизу вверх / сверху вниз × петли справа налево / слева направо; по умолчанию снизу вверх и справа налево; круговое вязание — потом), **шаг выделения** (каждая N-я линия жирнее), даты создания/изменения.

### Палитра
- Упорядоченный список нитей; практически без лимита (до 65 535 нитей, сверх — добавление отклоняется), UI рассчитан на ~30.
- Нить: цвет, узор заливки, необязательное имя/артикул.
- Узоры — фиксированная библиотека из 16 значков, по одному в центре клетки, в порядке назначения: × ● ○ + ■ / △ ◆ — □ \ ▼ | ◇ ⊙ ✳. Новой нити автоматически назначается первый незанятый значок; если заняты все — первый по порядку из наименее занятых. Совпадение узоров у двух нитей разрешено, но показывается предупреждение.
- Нити можно вручную выбрать «без узора»; автоматически он не назначается.
- **Номер нити** — её позиция в текущем порядке палитры; его видит пользователь (клавиши `1`–`9`, легенда). Перестановка нитей меняет номера, но не клетки (ADR-0004).
- **Перестановка нитей**: перетаскивание строки списка палитры за ручку ⋮⋮ (Pointer Events, без библиотеки); во время перетаскивания — линия-индикатор места вставки, `Esc` отменяет. Один бросок на новое место — одна правка; бросок на прежнее место правки не даёт. Текущая и предыдущая нить остаются теми же нитями (меняются только их номера). Клавиатурной альтернативы нет.
- Удаление используемой нити открывает диалог **замены нити** (на другую нить или «пусто»); удаление вместе с заменой — одна правка, один `Ctrl+Z` возвращает и клетки, и нить на прежнее место.
- «Заменить нить X на Y во всей схеме» — отдельное действие; X остаётся в палитре (с 0 петель).
- Палитра не бывает пустой: последнюю нить удалить нельзя («Удалить» неактивна с подсказкой). Поэтому текущая нить есть всегда.
- **Палитра по умолчанию** (первый запуск, восстановление не удалось, новая схема): две нити — 1 `#ffffff`, 2 `#000000`, узоры назначаются автоматически (× и ●); текущая — 1, предыдущая — 2; все клетки пустые.

## Редактор

### Раскладка экрана
Классическая раскладка, все элементы на компонентах Nuxt UI:
- **Сверху — строка меню** (`UDropdownMenu`, у пунктов клавиши через `kbds`): «Файл» (новая схема, открыть `.kchart`, сохранить в файл `.kchart`, экспорт PNG, экспорт PDF), «Правка» (отменить, повторить, размер схемы, свойства схемы), «Вид» (вписать, приблизить, отдалить, флажок подсветки ряда и столбца), «Справка» (горячие клавиши). В центре строки — название схемы, с маркером «•», если есть **изменения не в файле**. Справа — переключатель режима отображения: три кнопки в `UFieldGroup`.
- **Слева — столбец инструментов**: кнопки в вертикальной `UFieldGroup`, подсказка с клавишей через `UTooltip`. Внизу столбца — две последние нити (текущая поверх предыдущей), клик меняет их местами, как `X`.
- **В центре — холст** с линейками.
- **Справа — панель** шириной ~320 px с вкладками (`UTabs`):
  - «Палитра»: список нитей, в строке ручка перетаскивания ⋮⋮, номер (1–9 выделены), образец (цвет и значок), имя или «без имени», число петель и значок предупреждения при совпадении узора. Над списком — `UAlert` «у N нитей совпадают узоры», на вкладке — бейдж. Клик по строке выбирает нить, клик по образцу открывает поповер редактора нити. Внизу — «Добавить нить».
  - «Схема»: форма свойств схемы и кнопка «Изменить размер…». Изменение свойства — правка в момент фиксации поля: `blur` или `Enter` (у заметок — только `blur`) и только если значение изменилось; переключатели (нумерация, пропорция «авто/вручную») дают правку сразу. Некорректное число (плотность ≤ 0, шаг выделения < 1, пропорция ≤ 0) не принимается: поле показывает ошибку, правки нет.
- **Снизу — статус-бар**: ряд и петля под курсором в нумерации схемы, размер схемы, масштаб, инструмент, текущая нить, состояние автосохранения («сохранено» / «сохраняется…» / «автосохранение не работает», см. «Автосохранение») и метка «не в файле», если есть **изменения не в файле**.

**Поповер редактора нити** (`UPopover`, не модальный): `UColorPicker`, поле hex, выбор узора (17 кнопок: «без узора» и 16 значков, у занятых значков точка и подсказка «уже у N нит.»), предупреждение о совпадении, имя/артикул, «Заменить во всей схеме…», «Удалить». Клик по холсту при открытом поповере закрывает поповер **и** срабатывает как обычный клик инструмента (защиты нет, это осознанное решение). Пока поповер открыт или фокус в поле ввода, реестр горячих клавиш молчит.

### Диалоги
Все диалоги — `UModal`, кнопка основного действия справа в подвале.
- **Новая схема**: ширина и высота (`UInputNumber`, 1–500), плотность (петель × рядов на 10 см) и подсказка «готовое полотно ≈ X × Y см». Кнопки «Отмена» и «Создать».
- **Размер схемы**: четыре поля «сверху / снизу / слева / справа», расположенные вокруг схемы-миниатюры с итоговым размером (положительное число добавляет, отрицательное убирает). Если обрезаются непустые клетки — `UAlert` «будет обрезано N непустых клеток», а кнопка становится «Обрезать и применить».
- **Замена нити** (при удалении используемой нити и для «заменить во всей схеме»): удаляемая нить с числом петель, ниже сетка вариантов «Пусто («нет петли»)» и остальные нити. Кнопки «Заменить и удалить» / «Заменить» и «Отмена».
- **Сохранить изменения в файл?** (`dismissible: false`): «Отбросить» слева, «Отмена» и «Сохранить в файл» справа.
- **Экспорт PDF**: формат, ориентация, ширина клетки в мм, режим печати, перекрытие (нет / 1 / 2), флажок «титульный лист». Справа — превью: сколько листов схемы (и отдельно титульных листов) и раскладка листов сеткой с номерами; если альбомная/книжная ориентация дала бы меньше листов — подсказка «в альбомной — N листов». Кнопка «Скачать PDF».
- **Горячие клавиши**: таблица в две колонки, клавиши через `UKbd`, строится из реестра команд.
- **Ошибки и сообщения** (битый файл и т.п.) — toast.

### Холст
- Рабочая область рендерится в `<canvas>`.
- **Режим отображения**: цвет / узор / цвет+узор.
- В режиме «цвет+узор» значок чёрный или белый по яркости цвета нити (порог относительной яркости 0,18) — на экране и в PDF.
- Узоры рисуются при клетке от 8 CSS px; мельче режим «узор» показывает цвет нити.
- **Пустая клетка** во всех режимах и на печати показывается тонкой косой серой штриховкой «нет петли», чтобы не путаться с нитью без узора и с серой нитью.
- Колесо — прокрутка, Ctrl+колесо — зум относительно курсора, пробел+перетаскивание и средняя кнопка — панорамирование, «вписать в окно».

### Линейки
- Линейки X (петли) и Y (ряды) закреплены у краёв видимой области.
- Нумерация следует направлению нумерации схемы; каждая N-я метка выделена.
- Под курсором подсвечиваются номера на обеих линейках и (отключаемо) ряд и столбец на сетке.
- Статус-бар показывает координаты в нумерации схемы.

### Инструменты
- **Кисть**: 1×1, протягивание с интерполяцией пропущенных клеток (Брезенхем, 8-связность). Shift+клика нет.
- **Ластик**: делает клетки пустыми; протягивание — как у кисти.
- **Пипетка**: берёт нить клетки (также удержанием `Alt`). При протягивании нить берётся вживую, итог — на отпускании. На пустой клетке ничего не меняется («пусто» не бывает текущей нитью). После клика инструментом `I` возвращается прежний инструмент; временная пипетка `Alt` — до отпускания `Alt` (на `keyup` `Alt` — `preventDefault`, чтобы Firefox не показывал меню). Если взятая нить отличается от текущей, текущая становится предыдущей — как при выборе клавишей.
- **Заливка**: по 4-связности; пустые клетки образуют области так же, как нити (заливка по пустой клетке заливает связную пустую область). Считается только нажатие.
- **Линия**: Брезенхем, 8-связность. Shift — привязка к ближайшему из направлений 0° / 45° / 90° (диагональ строго 1:1 в клетках); конец — проекция курсора на это направление.
- **Прямоугольник**: контурный; с зажатым Shift — залитый. Shift читается вживую (предпросмотр переключается сразу), итог — по состоянию на отпускании. Ограничения «квадрат» нет.

**Жест** — от нажатия кнопки над сеткой до отпускания; один жест — не более одной правки.
- **Кнопки**: левая — текущей нитью, правая — предыдущей нитью (нижняя из пары в столбце инструментов). Ластик правой кнопкой работает как левой; пипетка правой кнопкой кладёт нить в слот предыдущей, текущую не трогая. Контекстное меню над холстом подавлено. Средняя кнопка — панорамирование.
- **Отмена**: `Esc` или нажатие второй кнопки во время жеста отменяет его целиком (мазок откатывается, предпросмотр пропадает, правки нет). `pointercancel`, потеря фокуса окна — как отпускание: жест фиксируется.
- **Предпросмотр** линии и прямоугольника — на overlay-canvas ровно как будущий результат (клетки в текущем режиме отображения, непрозрачно). Во время жеста статус-бар показывает размер: «12 × 5» у прямоугольника, «длина 14» у линии. Кисть и ластик меняют клетки сразу.
- **Край сетки**: жест, начатый вне сетки, ничего не делает. Во время жеста — pointer capture, выход за холст жест не прерывает. Кисть и ластик интерполируют между реальными позициями указателя и обрезают отрезки по сетке; линия обрезается (наклон сохраняется); угол прямоугольника прижимается к сетке.
- **Ввод во время жеста**: игнорируются смена инструмента и нити (`B`…`R`, `1`–`9`, `X`), undo/redo, `Tab`, пробел-панорамирование, `Alt`-пипетка. Работают колесо и `Ctrl+колесо` (указатель пересчитывается в клетки, интерполяция — в координатах сетки), `Esc` и Shift.
- **Без изменений — без правки**: если жест не изменил ни одной клетки (та же нить, ластик по пустым, заливка той же нитью, отменённый жест), правка не создаётся — нет записи в undo, не ставятся изменения не в файле, нет автосохранения.
- **Наведение**: над сеткой у всех инструментов — тонкая обводка клетки под курсором на overlay и курсор `crosshair`; у пипетки (инструмент `I` или зажатый `Alt`) — свой курсор-иконка через CSS `cursor: url(...)`. Вне сетки обводки нет.

**Критерии приёмки инструментов** (тесты domain/application, где возможно):
- мазок кистью → один `Ctrl+Z` откатывает его целиком; мазок правой кнопкой кладёт предыдущую нить;
- быстрый мазок без пропусков: соседние точки указателя через 5 клеток дают непрерывную 8-связную цепочку;
- `Esc` посреди мазка → клетки как до него, стек undo не изменился;
- мазок по клеткам той же нити / ластик по пустым / заливка той же нитью → стек undo не изменился, маркера «•» нет;
- линия с Shift под углом ~30° ложится горизонтально, под ~40° — диагонально 1:1;
- прямоугольник: отпускание с Shift → залитый, без Shift → контур, переключение Shift во время протягивания меняет предпросмотр;
- протягивание прямоугольника за край → прямоугольник до края сетки; линия за край → обрезана, наклон тот же;
- пипетка на пустой клетке → текущая нить не изменилась; `I` → клик → активен прежний инструмент;
- заливка по пустой клетке закрашивает только связную (4-связно) пустую область.

### Документ
- **Новая схема**: диалог с шириной, высотой (по умолчанию 40×40) и плотностью.
- **Изменение размера**: добавить или убрать N рядов/петель с каждой из четырёх сторон; если обрезаются непустые клетки, показывается предупреждение.
- Новая схема и импорт заменяют текущую. Если есть изменения не в файле, появляется диалог «Сохранить в файл / Отбросить / Отмена»; «Сохранить в файл» запускает скачивание `.kchart` и сразу продолжает.
- Текущая схема автоматически сохраняется в браузере (IndexedDB) и восстанавливается при перезагрузке — см. «Автосохранение».

### Изменения не в файле
Признак «в схеме есть то, чего нет в последнем сохранённом `.kchart`»; показывается маркером «•» у названия и меткой «не в файле» в статус-баре.
- При сохранении `.kchart` запоминается правка на вершине стека undo (или «история пуста»). Схема «чистая», когда вершина стека — та же правка: undo до точки сохранения снимает признак, redo обратно — снова ставит.
- Если запомненная правка покинула историю (ушла за глубину 200 или отброшена новой правкой после undo), признак держится до следующего сохранения.
- Признак снимают: запуск скачивания `.kchart` (успех записи на диск браузер не сообщает — считаем сохранённым), импорт `.kchart`, новая схема. Экспорт PNG и PDF признак не трогает.
- Первый запуск без автосохранения — пустая схема 40×40, «чистая».
- Признак хранится в автосохранении рядом с документом и переживает перезагрузку. После перезагрузки истории нет, поэтому «грязную» схему очищает только сохранение.

### Автосохранение
- **Когда**: через 500 мс после последней правки, undo или redo (debounce); при `visibilitychange → hidden` отложенная запись выполняется сразу. Записи идут строго последовательно; если во время записи пришла правка, следующая запись берёт самое свежее состояние.
- **Что**: одна запись в IndexedDB — документ v1 (см. «Файл схемы .kchart») и признак изменений не в файле.
- **Статус** в статус-баре: «сохранено»; «сохраняется…» — только если запись идёт дольше 300 мс; «автосохранение не работает» — красным, с подсказкой «сохраните схему в файл».
- **Ошибка записи** (IndexedDB недоступна, квота): статус «автосохранение не работает» и один toast на серию ошибок подряд; работа продолжается, каждая следующая правка снова пытается записать, успех возвращает статус «сохранено».
- **Закрытие страницы**: `beforeunload` предупреждает, только если автосохранение сейчас не работает **и** есть изменения не в файле.
- **Несколько вкладок**: писать может только вкладка, держащая Web Lock автосохранения. Вкладка, не получившая замок, схему не загружает и показывает поверх редактора экран «Редактор открыт в другой вкладке» с кнопкой «Работать здесь». Перехват: старая вкладка выполняет отложенную запись, отпускает замок и блокируется тем же экраном; новая берёт замок и читает схему из IndexedDB.
- **Восстановление не удалось** (запись не проходит миграции или проверки): сырая запись переносится в отдельный слот `autosave-broken` (один, перезаписывается следующим сбоем), toast «Не удалось восстановить схему» с кнопкой «Скачать как есть» (сырой JSON в файл), затем пустая схема 40×40.
- **Предпочтения вида** — отдельно от схемы, в `localStorage`: режим отображения, флажок подсветки ряда и столбца, текущий инструмент. Не сохраняются: текущая нить (при загрузке — первая), зум и прокрутка (при загрузке — «вписать»).

**Критерии приёмки**:
- правка → через ≤ 1 с перезагрузка → схема и признак восстановлены;
- сохранить `.kchart` → правка → undo → маркера «•» нет; redo → маркер есть;
- правка → перезагрузка → «Новая схема» показывает диалог «Сохранить изменения в файл?»;
- вторая вкладка показывает экран «Редактор открыт в другой вкладке»; «Работать здесь» показывает правки первой вкладки, а первая блокируется;
- битая запись в IndexedDB → toast с «Скачать как есть», пустая схема, запись лежит в `autosave-broken`;
- отказ IndexedDB при записи → статус «автосохранение не работает», один toast; `beforeunload` предупреждает.

### Undo / Redo
- Одна **правка** — одна запись: мазок целиком (от нажатия до отпускания), заливка, фигура, изменение палитры, замена нити, изменение размера, изменение свойств.
- Правками не являются: зум, прокрутка, выбор инструмента и нити, режим отображения.
- Глубина — 200 правок; история живёт только в сессии.
- Реализация — обратимые патчи (ADR-0001).

## Вывод

### Файл схемы `.kchart`
Компромиссы формата — ADR-0005.

- JSON в UTF-8, ключи camelCase в фиксированном порядке, форматированный; каждый ряд сетки пишется одной строкой. Имя файла по умолчанию — `<название>.kchart`, при пустом названии `схема.kchart`.
- Обёртка: `"format": "kchart"` и `"version": 1` (целое, растёт только при несовместимом изменении).
- `properties`: `title` (строка, может быть пустой), `notes` (строка), `gauge` — `{stitches, rows}` на 10 см, числа > 0, дробные допустимы, обязательна (по умолчанию 20×28), `cellAspect` — `{"mode": "auto"}` (из плотности) или `{"mode": "manual", "ratio": ширина/высота}`, `numbering` — `{"rows": "bottom-up" | "top-down", "stitches": "right-to-left" | "left-to-right"}`, `majorStep` — целое ≥ 1 (по умолчанию 10), `createdAt` / `modifiedAt` — ISO 8601 UTC; `modifiedAt` — время последней правки, а не сохранения.
- `palette`: нити в порядке палитры (номер = позиция с 1): `color` — `#rrggbb` строчными, `pattern` — код узора или `null` («без узора»), `name` — только если не пустое. Внутренние id нитей в файл не попадают: при импорте id = номер.
- Коды узоров в порядке назначения: × `cross`, ● `circle-filled`, ○ `circle-outline`, + `plus`, ■ `square-filled`, / `line-slash`, △ `triangle-up-outline`, ◆ `diamond-filled`, — `line-h`, □ `square-outline`, \ `line-backslash`, ▼ `triangle-down-filled`, | `line-v`, ◇ `diamond-outline`, ⊙ `circle-dot`, ✳ `asterisk`. Те же коды — идентификаторы узоров в domain.
- `grid`: `width`, `height` и `rows` — ряды в экранном порядке (сверху вниз), независимо от направления нумерации. Ряд — обязательный RLE: плоский массив `[номер, длина, номер, длина, …]`, 0 — пустая клетка, сумма длин = `width`.
- В файл не попадает состояние вида: режим отображения, масштаб, прокрутка, инструмент, текущая нить.

Пример (4×2):

```json
{
  "format": "kchart",
  "version": 1,
  "properties": {
    "title": "Олени",
    "notes": "",
    "gauge": { "stitches": 22.5, "rows": 30 },
    "cellAspect": { "mode": "auto" },
    "numbering": { "rows": "bottom-up", "stitches": "right-to-left" },
    "majorStep": 10,
    "createdAt": "2026-10-25T10:00:00.000Z",
    "modifiedAt": "2026-10-25T11:30:00.000Z"
  },
  "palette": [
    { "color": "#f4f1ea", "pattern": null },
    { "color": "#b22222", "pattern": "cross", "name": "Alize Lanagold 56" }
  ],
  "grid": {
    "width": 4,
    "height": 2,
    "rows": [
      [1, 4],
      [0, 1, 2, 2, 1, 1]
    ]
  }
}
```

**Импорт**: `JSON.parse` (BOM допускается) → проверка `format` → `version` (новее текущей — ошибка) → цепочка чистых миграций `vN → vN+1` над сырым JSON → строгая проверка схемой valibot **только текущей** версии → смысловые проверки (число рядов = `height`, сумма длин ряда = `width`, номер нити ≤ числа нитей, `width`/`height` 1–500, нитей ≤ 65 535) → схема. Неизвестные поля игнорируются. Терпимо читается: hex в любом регистре (приводится к строчному), RLE-пары с длиной 0 и соседние пары с одинаковым номером. Отклоняются: `#rgb`, нецелые и отрицательные длины и номера, нечисла.

Импорт битого или несовместимого файла не трогает текущую схему и показывает toast одной из категорий:
- «Это не файл схемы (.kchart)» — не JSON или нет `format: "kchart"`;
- «Файл создан более новой версией редактора»;
- «Файл повреждён: <деталь>» — деталь в нумерации с 1, ряды по порядку файла сверху, например «ряд 12: длина 38 вместо 40», «ряд 3: нить 7, а в палитре 5»;
- «Схема слишком большая: максимум 500×500»;
- «Слишком много нитей: максимум 65 535».

**Автосохранение** в IndexedDB хранит тот же документ v1 (объект, а не строку) тем же сериализатором и при восстановлении проходит те же миграции и проверки. Id нитей при восстановлении перенумеровываются — это безопасно, пока история правок не переживает перезагрузку (ADR-0004).

**Критерии приёмки сериализатора**:
- в `fixtures/kchart/v1/` лежат корректные образцы и по одному битому на каждую категорию ошибки; тесты проверяют текст категории;
- круговой путь «схема → файл → схема» даёт равную схему (сравнение по номерам нитей, не по id); запись канонична (повторная запись прочитанного файла даёт тот же текст);
- для каждой будущей версии N в `fixtures/kchart/vN/` лежит образец, который мигрирует до текущей версии и проходит проверку.

### PNG
Растровый экспорт текущего режима отображения с линейками.
- Без диалога: «Файл» → «Экспорт PNG» сразу скачивает `<название>.png`, при пустом названии `схема.png`.
- Ширина клетки — 20 px, высота — ширина / пропорция клетки; если длинная сторона картинки вышла бы больше 8192 px, ширина клетки уменьшается до наибольшего целого, при котором картинка помещается (500×500 → 16 px). Узоры рисуются по тому же порогу 8 px, что и на экране.
- Линейки — как на экране (сверху и слева), в нумерации схемы, с выделением каждой N-й метки; сетка и линии шага выделения есть; подсветки ряда и столбца и обводки под курсором нет. Масштаб и прокрутка вида на картинку не влияют.

### PDF
- Векторный (без растра). Имя файла — `<название>.pdf`, при пустом названии `схема.pdf`.
- Формат A4/A3, книжная или альбомная ориентация (одна на весь документ). Поля страницы фиксированные — 10 мм.
- Ширина клетки в мм: 2–20, шаг 0,5, по умолчанию 5; высота = ширина / пропорция клетки. Режима «вписать в N листов» нет.
- Режим печати: цвет / узор / цвет+узор.

**Нарезка на листы схемы**:
- Из размера клетки и области сетки (страница минус поля, линейки и колонтитул) получается вместимость листа в петлях и рядах. Уникальная часть листа — наибольшее кратное шагу выделения, не больше вместимости за вычетом перекрытия (если она меньше шага — сама эта величина); листы заполняются до предела, последний в ряду/столбце получает остаток.
- **Перекрытие** (нет / 1 / 2, по умолчанию нет): на каждом внутреннем стыке следующий лист повторяет у стыка последние N петель или рядов предыдущего, сверх своей уникальной части. Повторённые клетки рисуются как обычно; граница перекрытия на повторяющем листе — пунктирная «линия склейки». На внешних краях схемы перекрытия нет.
- Порядок листов следует направлению нумерации: лист 1 содержит ряд 1 и петлю 1; дальше — вдоль петель, затем вдоль рядов.
- Неполный лист прижимается к тому же углу области сетки, что и полные, так что начало сетки на всех листах совпадает по модулю размера клетки и весь документ обходится одним набором tiling patterns.

**Каждый лист схемы**:
- Линейки со всех четырёх сторон, сквозная нумерация по направлению нумерации схемы, каждая N-я метка выделена. Номер стоит у каждой клетки, если клетка по этой оси ≥ 4 мм, иначе только у каждой N-й (шаг выделения). Шрифт номеров ~2 мм.
- Нижний колонтитул: название, «Лист 3 из 12», «ряды 41–80, петли 1–60» (в нумерации схемы, включая перекрытие) и миниатюра раскладки листов с выделенным текущим.

**Титульный лист** (флажок, по умолчанию включён; выключен — PDF только из листов схемы):
- Сверху вниз: название (пустое — «Схема»), размер «60 петель × 80 рядов», плотность и «готовое полотно ≈ X × Y см», заметки, **легенда**, крупная миниатюра раскладки листов с номерами.
- Не поместилось — легенда и заметки продолжаются на следующем титульном листе («Титульный лист 2 из 2»). Листы схемы нумеруются отдельно, с 1.
- **Легенда**: номер нити → образец (в режиме печати) → имя или «без имени» → число петель. Порядок палитры; нити с 0 петель не показываются, номера остальных — палитровые (с пропусками). Под таблицей — сноска с образцом штриховки: «нет петли».

**Критерии приёмки раскладки** (тесты чистой функции раскладки):
- 100 петель при вместимости 64 и шаге 10 → листы по 60 и 40 петель; при перекрытии 2 второй лист показывает петли 59–100;
- вместимость 7 при шаге 10 → листы по 7;
- нумерация по умолчанию → лист 1 содержит правый нижний угол схемы;
- начало сетки на всех листах, включая неполные, совпадает по модулю ширины и высоты клетки;
- нить с 0 петель отсутствует в легенде, номер следующей за ней нити не сдвигается;
- клетка 3 мм при шаге 10 → на линейке только номера 10, 20, …; клетка 5 мм → все номера.

## Архитектура

- TypeScript (strict), Vue 3 (Composition API), Vite.
- Библиотека компонентов UI — Nuxt UI (в режиме Vue + Vite, без Nuxt).
- Слои (ADR-0002):
  - **domain** — схема, сетка, палитра, нить, узоры, правки и патчи, алгоритмы инструментов (линия, заливка). Чистый TS.
    - Узор описывается векторными примитивами в единичном квадрате клетки (отрезок, круг, окружность, многоугольник, ломаная; толщина в долях клетки). Одно описание рисуется в штамп клетки на canvas и в tiling pattern jsPDF (матрица «квадрат → клетка» в конструкторе `TilingPattern`). При пропорции клетки не 1:1 узор растягивается вместе с клеткой. Минимальная толщина линии — 1 device px на экране, 0,25 мм в PDF.
  - **application** — сценарии (рисовать, залить, заменить нить, изменить размер, undo/redo, импорт/экспорт) и порты (хранилище, файлы, PDF, PNG).
  - **infrastructure** — canvas-рендерер, IndexedDB, сериализация `.kchart`, генератор PDF (jsPDF, ленивая загрузка), PNG.
  - **presentation** — Vue-компоненты, реестр горячих клавиш, перевод пикселей холста в клетки. Pinia нет (ADR-0006).
- Папки: `src/domain`, `src/application`, `src/infrastructure`, `src/presentation`; корень сборки — `src/main.ts`.
- Импорты: domain — ничего; application → domain; infrastructure → application (реализует порты), domain; presentation → application, domain, но не infrastructure. Адаптеры (canvas-рендерер, IndexedDB, jsPDF, `Clock`) создаёт только `src/main.ts` и передаёт во Vue через `provide`.
- Проверка границ (domain и application не импортируют Vue, DOM и canvas):
  - `eslint-plugin-boundaries` по матрице импортов выше;
  - `no-restricted-imports`: `vue`, `@nuxt/*`, `jspdf` запрещены в domain и application;
  - `tsconfig.core.json` для domain + application с `lib: ["ES2023"]` без DOM — `document`, `window`, `HTMLCanvasElement` в ядре — ошибка типов;
  - ESLint 9, flat config.

### Сессия редактора (ADR-0006)
- Один модуль application: `state` только для чтения, `dispatch(команда)` (правки, undo/redo, выбор инструмента и т. п.), `subscribe(listener)`.
- События одного потока: `patch` — применённый патч (правка, undo, redo); `preview` — изменился предпросмотр жеста (только overlay); `replaced` — документ заменён целиком (открыт файл, импорт, новая схема).
- Подписчики: composable `useEditor()` (`shallowRef` + счётчик версии), canvas-рендерер (по `patch` перерисовывает изменённые клетки, по `replaced` — всё), автосохранение (debounce по `patch`/`replaced`, `preview` игнорирует).
- Жест ведёт сессия: получает `pointerDown/Move/Up/Cancel` в координатах клеток (ряд, петля, кнопка, Shift), держит предпросмотр и коммитит не более одной правки. Presentation переводит пиксели в клетки и клавиши в команды.
- Ядро не возвращает текст: результаты и ошибки — типизированные коды (категории ошибок `.kchart`, «палитра полна», …); строки — только в словаре vue-i18n в presentation.
- Время — через порт `Clock` (`now(): Date`); в Vitest — фиксированный адаптер.
- Сетка — плоский типизированный массив (`Uint16Array`) стабильных id нитей; 0 — пустая клетка (ADR-0004). id выдаётся при создании нити — наименьший свободный ≥ 1; рендер и легенда сопоставляют id с нитью через таблицу.

### E2E (Playwright)

Задача e2e — доказать, что части работают вместе в настоящем браузере; логику (правки, сериализатор, раскладку PDF) проверяют тесты Vitest.

**Механизм**:
- В коде приложения нет тестовых хуков. Источники истины — наблюдаемые выходы: скачанный `.kchart` (тест парсит JSON и сравнивает сетку по номерам нитей), видимый текст UI (число петель в палитре, статус-бар, маркер «•», toast) и пиксели холста.
- **Пиксельная проба**: `page.evaluate` читает `getImageData` основного bitmap-canvas в точке у угла клетки со сдвигом от края (мимо значка узора и линий сетки) и сравнивает с hex нити, допуск ±2 на канал. Скриншот-сравнений нет.
- Попадание в клетку: viewport 1280×800, `deviceScaleFactor: 1`, «Вписать», схемы в тестах маленькие (например, 10×8). Helper `cellCenter(ряд, петля)` считает точку по `boundingBox` холста и размеру схемы, наводит курсор и сверяет ряд и петлю в статус-баре до клика.
- PDF: скачанный файл разбирается `pdfjs-dist` в тесте: число страниц равно превью диалога, есть тексты колонтитула («Лист 1 из N», «ряды …, петли …»), имена нитей и «нет петли» на титульном листе, в operator list нет `paintImageXObject` (векторный). Геометрию листов e2e не проверяет.
- Время: `page.clock.install()` с фиксированной датой — `createdAt`/`modifiedAt` в файле предсказуемы. Ожидания — только по видимому состоянию («сохранено», toast, событие download), без `waitForTimeout`.
- Локаторы — роли и доступные имена из русского словаря. `data-testid` — только у слоёв canvas (основной, overlay, линейки); холст имеет `aria-label` «Схема».
- «Открыть `.kchart`» — через `<input type="file">` (не File System Access API), тест использует `setInputFiles`.
- e2e идут по прод-сборке (`vite build` + `vite preview`) с тем же base path, что у GitHub Pages.
- Браузер — только Chromium. В CI `retries: 1`, `trace: 'on-first-retry'`, отчёт Playwright выкладывается артефактом; локально без ретраев.

**Сценарии** (каждый — критерий приёмки той задачи реализации, что приносит функцию):
1. *Этап 1*: кистью несколько клеток двумя нитями → ластик → undo → redo (пробы и число петель после каждого шага) → «Сохранить в файл» → чистое хранилище → «Открыть» этот файл → пробы те же, `.kchart` совпадает.
2. *Этап 1*: нарисовать → перезагрузить → схема на месте, метка «не в файле» сохранилась; после «Сохранить в файл» и перезагрузки метки нет.
3. *Этап 1*: открыть каждый битый образец из `fixtures/kchart/v1/` → toast своей категории, схема не тронута.
4. *Этап 1*: вторая вкладка не захватывает автосохранение (Web Lock) и показывает соответствующее состояние.
5. *Этап 3*: экспорт PDF в каждом режиме печати — проверки выше; с титульным листом и без.
6. *Этап 3*: экспорт PNG — размеры картинки и пиксельная проба цвета клетки.

## Этапы

1. **Ядро**: модель схемы, canvas-рендер сетки, линейки с подсветкой, зум/прокрутка, палитра, кисть, ластик, пипетка, undo/redo, реестр горячих клавиш, автосохранение, экспорт/импорт `.kchart`, каркас CI и деплоя.
   - Узоры в этапе 1 есть только в domain и файле: новой нити узор назначается автоматически, `.kchart` его пишет и читает; рисовка, выбор в поповере и предупреждение о совпадении — этап 2.
   - Палитра в этапе 1: добавить, выбрать, цвет/hex/имя, удалить **неиспользуемую** нить; у используемой «Удалить» неактивна с подсказкой до диалога замены нити (этап 2). Перестановки нитей в этапе 1 нет.
   - UI будущих этапов (новая схема, размер, свойства и вкладка «Схема», режимы отображения, экспорт PNG/PDF) не показывается, пока его не принесёт своя задача; мёртвых кнопок нет. Диалог «Сохранить изменения в файл?» в этапе 1 срабатывает перед «Открыть».
2. **Инструменты и документ**: заливка, линия, прямоугольник, новая схема, изменение размера, замена нити, перестановка нитей, свойства схемы, узоры заливки, режимы отображения.
   - Задачи с UI в этапах 2 и 3 закрываются ещё и коротким e2e (пиксельная проба или скачанный `.kchart`); логику проверяет Vitest.
3. **Вывод**: PNG, PDF с листами, линейками и легендой.
4. **Потом**: см. «Не входит».
