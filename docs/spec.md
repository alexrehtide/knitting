# Спецификация: редактор вязальных схем

Верхнеуровневая спецификация для запуска цикла wayfinder. Термины — по [CONTEXT.md](../CONTEXT.md); архитектурные решения — в [docs/adr/](adr/).

## Цель

Фронтенд-приложение для составления цветных схем для вязания (спицы, крючок): клетчатая **схема**, где каждая **клетка** — петля, окрашенная **нитью** из **палитры**. Схема печатается в PDF с **линейками** и читается на ч/б принтере благодаря **узорам заливки**.

## Рамки

- Только фронтенд, без бэкенда. Одна открытая схема за раз.
- Десктопный браузер, мышь/трекпад. Только актуальные Chrome, Edge, Firefox, Safari (последние две версии), без полифиллов.
- Интерфейс на русском; все строки — через словарь (vue-i18n).
- Деплой: GitHub Pages из `main` через GitHub Actions.

### Не входит (этап «Потом»)

Выделение / копирование / вставка / отражение; символы петель (лицевая, изнаночная и т.п.); импорт картинок и чужих форматов; раппорт; кисть больше 1×1; тач и стилус; PWA/офлайн; переназначение клавиш; библиотека из нескольких схем; сохранение истории правок между перезагрузками.

Модель клетки и обработка ввода не должны закрывать дорогу этим расширениям: содержимое клетки расширяемо, ввод — через Pointer Events, команды — через единый реестр.

## Модель

### Схема
- Конечная сетка W×H, целевой максимум ~500×500 с плавной работой.
- Каждая клетка: ссылка на нить палитры или **пустая клетка**.
- **Свойства схемы**: название, заметки (свободный текст), **плотность вязания** (петель и рядов на 10 см), **пропорция клетки** (переключатель: «авто» — из плотности, или вручную, по умолчанию 1:1), **направление нумерации** (одна из 4 комбинаций: ряды снизу вверх / сверху вниз × петли справа налево / слева направо; по умолчанию снизу вверх и справа налево; круговое вязание — потом), **шаг выделения** (каждая N-я линия жирнее), даты создания/изменения.

### Палитра
- Упорядоченный список нитей; практически без лимита (до 65 535 нитей, сверх — добавление отклоняется), UI рассчитан на ~30.
- Нить: цвет, узор заливки, необязательное имя/артикул.
- Узоры — фиксированная библиотека из 16 значков, по одному в центре клетки, в порядке назначения: × ● ○ + ■ / △ ◆ — □ \ ▼ | ◇ ⊙ ✳. Новой нити автоматически назначается первый незанятый значок; если заняты все — первый по порядку из наименее занятых. Совпадение узоров у двух нитей разрешено, но показывается предупреждение.
- Нити можно вручную выбрать «без узора»; автоматически он не назначается.
- **Номер нити** — её позиция в текущем порядке палитры; его видит пользователь (клавиши `1`–`9`, легенда). Перестановка нитей меняет номера, но не клетки (ADR-0004).
- Удаление используемой нити открывает диалог **замены нити** (на другую нить или «пусто»); удаление вместе с заменой — одна правка, один `Ctrl+Z` возвращает и клетки, и нить на прежнее место.
- «Заменить нить X на Y во всей схеме» — отдельное действие; X остаётся в палитре (с 0 петель).

## Редактор

### Раскладка экрана
Классическая раскладка, все элементы на компонентах Nuxt UI:
- **Сверху — строка меню** (`UDropdownMenu`, у пунктов клавиши через `kbds`): «Файл» (новая схема, открыть `.kchart`, сохранить в файл `.kchart`, экспорт PNG, экспорт PDF), «Правка» (отменить, повторить, размер схемы, свойства схемы), «Вид» (вписать, приблизить, отдалить, флажок подсветки ряда и столбца), «Справка» (горячие клавиши). В центре строки — название схемы, с маркером «•», если есть изменения после сохранения в файл. Справа — переключатель режима отображения: три кнопки в `UFieldGroup`.
- **Слева — столбец инструментов**: кнопки в вертикальной `UFieldGroup`, подсказка с клавишей через `UTooltip`. Внизу столбца — две последние нити (текущая поверх предыдущей), клик меняет их местами, как `X`.
- **В центре — холст** с линейками.
- **Справа — панель** шириной ~320 px с вкладками (`UTabs`):
  - «Палитра»: список нитей, в строке номер (1–9 выделены), образец (цвет и значок), имя или «без имени», число петель и значок предупреждения при совпадении узора. Над списком — `UAlert` «у N нитей совпадают узоры», на вкладке — бейдж. Клик по строке выбирает нить, клик по образцу открывает поповер редактора нити. Внизу — «Добавить нить».
  - «Схема»: форма свойств схемы и кнопка «Изменить размер…».
- **Снизу — статус-бар**: ряд и петля под курсором в нумерации схемы, размер схемы, масштаб, инструмент, текущая нить, состояние автосохранения и метка «не в файле», если есть изменения после последнего сохранения в `.kchart`.

**Поповер редактора нити** (`UPopover`, не модальный): `UColorPicker`, поле hex, выбор узора (17 кнопок: «без узора» и 16 значков, у занятых значков точка и подсказка «уже у N нит.»), предупреждение о совпадении, имя/артикул, «Заменить во всей схеме…», «Удалить». Клик по холсту при открытом поповере закрывает поповер **и** срабатывает как обычный клик инструмента (защиты нет, это осознанное решение). Пока поповер открыт или фокус в поле ввода, реестр горячих клавиш молчит.

### Диалоги
Все диалоги — `UModal`, кнопка основного действия справа в подвале.
- **Новая схема**: ширина и высота (`UInputNumber`, 1–500), плотность (петель × рядов на 10 см) и подсказка «готовое полотно ≈ X × Y см». Кнопки «Отмена» и «Создать».
- **Размер схемы**: четыре поля «сверху / снизу / слева / справа», расположенные вокруг схемы-миниатюры с итоговым размером (положительное число добавляет, отрицательное убирает). Если обрезаются непустые клетки — `UAlert` «будет обрезано N непустых клеток», а кнопка становится «Обрезать и применить».
- **Замена нити** (при удалении используемой нити и для «заменить во всей схеме»): удаляемая нить с числом петель, ниже сетка вариантов «Пусто («нет петли»)» и остальные нити. Кнопки «Заменить и удалить» / «Заменить» и «Отмена».
- **Сохранить изменения в файл?** (`dismissible: false`): «Отбросить» слева, «Отмена» и «Сохранить в файл» справа.
- **Экспорт PDF**: формат, ориентация, ширина клетки в мм, режим печати, перекрытие (нет / 1 / 2), флажки «заголовок» и «легенда». Справа — превью: сколько листов и раскладка листов сеткой. Кнопка «Скачать PDF».
- **Горячие клавиши**: таблица в две колонки, клавиши через `UKbd`, строится из реестра команд.
- **Ошибки и сообщения** (битый файл и т.п.) — toast.

### Холст
- Рабочая область рендерится в `<canvas>`.
- **Режим отображения**: цвет / узор / цвет+узор.
- В режиме «цвет+узор» значок чёрный или белый по яркости цвета нити (порог относительной яркости 0,18) — на экране и в PDF.
- Узоры рисуются при клетке от 8 CSS px; мельче режим «узор» показывает цвет нити.
- **Пустая клетка** во всех режимах и на печати показывается тонкой косой серой штриховкой «нет петли», чтобы не путаться с нитью без узора и с серой нитью.
- Колесо — прокрутка, Ctrl+колесо — зум относительно курсора, пробел+перетаскивание и средняя кнопка — панорамирование, «вписать в окно».

### Линейки
- Линейки X (петли) и Y (ряды) закреплены у краёв видимой области.
- Нумерация следует направлению нумерации схемы; каждая N-я метка выделена.
- Под курсором подсвечиваются номера на обеих линейках и (отключаемо) ряд и столбец на сетке.
- Статус-бар показывает координаты в нумерации схемы.

### Инструменты
- **Кисть**: 1×1, протягивание с интерполяцией пропущенных клеток; Shift+клик — линия от последней точки.
- **Ластик**: делает клетки пустыми.
- **Пипетка**: берёт нить клетки (также удержанием Alt).
- **Заливка**: по 4-связности.
- **Линия**.
- **Прямоугольник**: контурный, с модификатором — залитый.

### Документ
- **Новая схема**: диалог с шириной, высотой (по умолчанию 40×40) и плотностью.
- **Изменение размера**: добавить или убрать N рядов/петель с каждой из четырёх сторон; если обрезаются непустые клетки, показывается предупреждение.
- Новая схема и импорт заменяют текущую. Если были изменения после последнего экспорта в файл, появляется диалог «Сохранить в файл / Отбросить / Отмена».
- Текущая схема автоматически сохраняется в браузере (IndexedDB) и восстанавливается при перезагрузке.

### Undo / Redo
- Одна **правка** — одна запись: мазок целиком (от нажатия до отпускания), заливка, фигура, изменение палитры, замена нити, изменение размера, изменение свойств.
- Правками не являются: зум, прокрутка, выбор инструмента и нити, режим отображения.
- Глубина — 200 правок; история живёт только в сессии.
- Реализация — обратимые патчи (ADR-0001).

### Горячие клавиши
Привязка по `event.code` (работает в русской раскладке); все команды — в едином реестре.

| Клавиша | Команда |
|---|---|
| `B` / `E` / `G` / `I` / `L` / `R` | кисть / ластик / заливка / пипетка / линия / прямоугольник |
| удержание `Alt` | временная пипетка |
| `Ctrl+Z` | отменить |
| `Ctrl+Shift+Z`, `Ctrl+Y` | повторить |
| `Ctrl+S` | экспорт `.kchart` |
| `Ctrl+O` | импорт `.kchart` |
| `Ctrl+P` | экспорт PDF |
| `Ctrl+N` / `Alt+N` | новая схема (`Alt+N` — запасной: Chrome не отдаёт Ctrl+N) |
| `1`–`9` | нить по номеру в палитре |
| `X` | переключиться между двумя последними нитями |
| `Ctrl+0` / `Ctrl+=` / `Ctrl+-` | вписать / приблизить / отдалить |
| `Tab` | следующий режим отображения |
| `?` | справка по клавишам |

## Вывод

### Файл схемы `.kchart`
Компромиссы формата — ADR-0005.

- JSON в UTF-8, ключи camelCase в фиксированном порядке, форматированный; каждый ряд сетки пишется одной строкой. Имя файла по умолчанию — `<название>.kchart`, при пустом названии `схема.kchart`.
- Обёртка: `"format": "kchart"` и `"version": 1` (целое, растёт только при несовместимом изменении).
- `properties`: `title` (строка, может быть пустой), `notes` (строка), `gauge` — `{stitches, rows}` на 10 см, числа > 0, дробные допустимы, обязательна (по умолчанию 20×28), `cellAspect` — `{"mode": "auto"}` (из плотности) или `{"mode": "manual", "ratio": ширина/высота}`, `numbering` — `{"rows": "bottom-up" | "top-down", "stitches": "right-to-left" | "left-to-right"}`, `majorStep` — целое ≥ 1 (по умолчанию 10), `createdAt` / `modifiedAt` — ISO 8601 UTC; `modifiedAt` — время последней правки, а не сохранения.
- `palette`: нити в порядке палитры (номер = позиция с 1): `color` — `#rrggbb` строчными, `pattern` — код узора или `null` («без узора»), `name` — только если не пустое. Внутренние id нитей в файл не попадают: при импорте id = номер.
- Коды узоров в порядке назначения: × `cross`, ● `circle-filled`, ○ `circle-outline`, + `plus`, ■ `square-filled`, / `line-slash`, △ `triangle-up-outline`, ◆ `diamond-filled`, — `line-h`, □ `square-outline`, \ `line-backslash`, ▼ `triangle-down-filled`, | `line-v`, ◇ `diamond-outline`, ⊙ `circle-dot`, ✳ `asterisk`. Те же коды — идентификаторы узоров в domain.
- `grid`: `width`, `height` и `rows` — ряды в экранном порядке (сверху вниз), независимо от направления нумерации. Ряд — обязательный RLE: плоский массив `[номер, длина, номер, длина, …]`, 0 — пустая клетка, сумма длин = `width`.
- В файл не попадает состояние вида: режим отображения, масштаб, прокрутка, инструмент, текущая нить.

Пример (4×2):

```json
{
  "format": "kchart",
  "version": 1,
  "properties": {
    "title": "Олени",
    "notes": "",
    "gauge": { "stitches": 22.5, "rows": 30 },
    "cellAspect": { "mode": "auto" },
    "numbering": { "rows": "bottom-up", "stitches": "right-to-left" },
    "majorStep": 10,
    "createdAt": "2026-10-25T10:00:00.000Z",
    "modifiedAt": "2026-10-25T11:30:00.000Z"
  },
  "palette": [
    { "color": "#f4f1ea", "pattern": null },
    { "color": "#b22222", "pattern": "cross", "name": "Alize Lanagold 56" }
  ],
  "grid": {
    "width": 4,
    "height": 2,
    "rows": [
      [1, 4],
      [0, 1, 2, 2, 1, 1]
    ]
  }
}
```

**Импорт**: `JSON.parse` (BOM допускается) → проверка `format` → `version` (новее текущей — ошибка) → цепочка чистых миграций `vN → vN+1` над сырым JSON → строгая проверка схемой valibot **только текущей** версии → смысловые проверки (число рядов = `height`, сумма длин ряда = `width`, номер нити ≤ числа нитей, `width`/`height` 1–500, нитей ≤ 65 535) → схема. Неизвестные поля игнорируются. Терпимо читается: hex в любом регистре (приводится к строчному), RLE-пары с длиной 0 и соседние пары с одинаковым номером. Отклоняются: `#rgb`, нецелые и отрицательные длины и номера, нечисла.

Импорт битого или несовместимого файла не трогает текущую схему и показывает toast одной из категорий:
- «Это не файл схемы (.kchart)» — не JSON или нет `format: "kchart"`;
- «Файл создан более новой версией редактора»;
- «Файл повреждён: <деталь>» — деталь в нумерации с 1, ряды по порядку файла сверху, например «ряд 12: длина 38 вместо 40», «ряд 3: нить 7, а в палитре 5»;
- «Схема слишком большая: максимум 500×500»;
- «Слишком много нитей: максимум 65 535».

**Автосохранение** в IndexedDB хранит тот же документ v1 (объект, а не строку) тем же сериализатором и при восстановлении проходит те же миграции и проверки. Id нитей при восстановлении перенумеровываются — это безопасно, пока история правок не переживает перезагрузку (ADR-0004).

**Критерии приёмки сериализатора**:
- в `fixtures/kchart/v1/` лежат корректные образцы и по одному битому на каждую категорию ошибки; тесты проверяют текст категории;
- круговой путь «схема → файл → схема» даёт равную схему (сравнение по номерам нитей, не по id); запись канонична (повторная запись прочитанного файла даёт тот же текст);
- для каждой будущей версии N в `fixtures/kchart/vN/` лежит образец, который мигрирует до текущей версии и проходит проверку.

### PNG
Растровый экспорт текущего режима отображения с линейками.

### PDF
- Векторный (без растра).
- Формат A4/A3, книжная или альбомная ориентация.
- Размер клетки в мм (по умолчанию ~5 мм) с учётом пропорции клетки.
- Большая схема разбивается на **листы**; на каждом повторяются линейки со сквозной нумерацией, опционально с перекрытием в 1–2 ряда/петли для склейки.
- Режим печати: цвет / узор / цвет+узор.
- Заголовок: название, размер, плотность, заметки.
- **Легенда**: нить → цвет/узор → имя → число петель этой нити.

## Архитектура

- TypeScript (strict), Vue 3 (Composition API), Vite.
- Библиотека компонентов UI — Nuxt UI (в режиме Vue + Vite, без Nuxt).
- Слои (ADR-0002):
  - **domain** — схема, сетка, палитра, нить, узоры, правки и патчи, алгоритмы инструментов (линия, заливка). Чистый TS.
    - Узор описывается векторными примитивами в единичном квадрате клетки (отрезок, круг, окружность, многоугольник, ломаная; толщина в долях клетки). Одно описание рисуется в штамп клетки на canvas и в tiling pattern jsPDF (матрица «квадрат → клетка» в конструкторе `TilingPattern`). При пропорции клетки не 1:1 узор растягивается вместе с клеткой. Минимальная толщина линии — 1 device px на экране, 0,25 мм в PDF.
  - **application** — сценарии (рисовать, залить, заменить нить, изменить размер, undo/redo, импорт/экспорт) и порты (хранилище, файлы, PDF, PNG).
  - **infrastructure** — canvas-рендерер, IndexedDB, сериализация `.kchart`, генератор PDF (jsPDF, ленивая загрузка), PNG.
  - **presentation** — Vue-компоненты; Pinia (если нужна) — тонкий мост между application и UI.
- domain и application не импортируют Vue, DOM и canvas; границы слоёв проверяет линтер (`eslint-plugin-boundaries` или аналог).
- Сетка — плоский типизированный массив (`Uint16Array`) стабильных id нитей; 0 — пустая клетка (ADR-0004). id выдаётся при создании нити — наименьший свободный ≥ 1; рендер и легенда сопоставляют id с нитью через таблицу.

### Качество
- ESLint + Prettier, строгий TS.
- Vitest: domain и application пишутся test-first.
- Playwright: несколько e2e-сценариев (нарисовать → undo → экспорт/импорт; печать PDF).

1. **Ядро**: модель схемы, canvas-рендер сетки, линейки с подсветкой, зум/прокрутка, палитра, кисть, ластик, пипетка, undo/redo, реестр горячих клавиш, автосохранение, экспорт/импорт `.kchart`, каркас CI и деплоя.
2. **Инструменты и документ**: заливка, линия, прямоугольник, новая схема, изменение размера, замена нити, свойства схемы, узоры заливки, режимы отображения.
3. **Вывод**: PNG, PDF с листами, линейками и легендой.
4. **Потом**: см. «Не входит».
