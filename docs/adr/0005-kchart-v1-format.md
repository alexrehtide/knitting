# Формат .kchart v1: RLE по рядам в экранном порядке, общий с автосохранением

Сетка в файле — массив рядов сверху вниз, каждый ряд — обязательный RLE `[номер, длина, …]`. Плоский массив проще, но 500×500 даёт ~0,7 МБ, и в файле не видно рядов; base64 от `Uint16Array` компактнее, но файл не прочесть и не сравнить в git. Ряд как строка RLE читается глазами, diff показывает изменённые ряды, а единственное кодирование (не «можно с RLE, можно без») проверяется однозначно. Ряды лежат в экранном порядке, а не в порядке нумерации: направление нумерации — только подписи, его смена не переписывает сетку (как перестановка нитей по ADR-0004). Узор нити записан строковым кодом (`cross`, `circle-filled`, …), а не индексом в библиотеке, чтобы смена порядка назначения или новые значки не ломали старые файлы. Автосохранение в IndexedDB хранит тот же документ v1 и проходит те же миграции и проверки: один формат, одна цепочка миграций, восстановление проверено тем же кодом, что импорт. Цена — id нитей при восстановлении перенумеровываются, поэтому если история правок когда-нибудь станет переживать перезагрузку, автосохранению понадобится свой формат с id.
